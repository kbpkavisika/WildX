# Handoff: ranger mobile app (Expo) with offline sync

Branch: `feat/ranger-mobile-app-offline-sync`. Nothing is committed (the user has not asked for a commit). Date: 9 Oct 2026.

## The task

Build a React Native (Expo) app in `mobile/` for the **Ranger** role only. It must cover every ranger step in `docs/requirements.md`, follow `docs/DESIGN.md` exactly, and make all ranger writes work offline. Writes go to a local SQLite outbox first and are resent until the server accepts them.

Rules from `AGENTS.md`: no code comments, keep it simple, never commit or branch unless asked. DESIGN.md is the source of truth for UI. Run the `wildx-dev` skill workflow. `mobile/AGENTS.md`, generated by the Expo template, says SDK 57 APIs differ from older SDKs: check `https://docs.expo.dev/versions/v57.0.0/` before you use an Expo API.

The full plan is in `docs/superpowers/plans/2026-10-09-ranger-mobile-app.md`.

## Decisions the user approved

1. **Backend idempotency.** An incident carries a client UUID `clientId`. If the same action on a dispatch or alert is sent again, the server returns the saved state instead of 400.
2. **Maps.** Use `react-native-maps` with an OpenStreetMap `UrlTile`.
3. **Background GPS.** Recording continues with the screen locked (`expo-location` + `expo-task-manager`), which needs a dev build. If background tracking is not available (Expo Go, or permission refused), the app falls back to a foreground watch.
4. **Docs first.** requirements.md, architecture.md and DESIGN.md were updated before any code.

Out of scope: the CMN-10 language switch and push notifications. The app polls instead.

## Key behaviour to preserve
- Every ranger write calls `save()` / `saveForUser()`, which inserts an outbox row and then triggers `syncNow()`. The UI confirms as soon as the row is saved.
- The sync loop sends rows in FIFO order and batches consecutive track points of one patrol (up to 1000).
  - A network error, 5xx, 408, 429 or 401 stops the loop and keeps the row.
  - Any other 4xx marks the row `REJECTED` with the server message.
  - On success, the loop refreshes the related queries, then deletes the row and its photo.
- Sync triggers: app start, network coming back, app returning to the foreground, every 30 s while rows wait, and every new row.
- Logout keeps outbox rows; they sync the next time the same ranger signs in. Rows are scoped by `user_id`.
